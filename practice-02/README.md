## 4. Модель данных и функции

**Модель задачи:** `{ id, title, completed, priority }`.

- `id` — положительное безопасное целое число (`Number.isSafeInteger(id)` и `id > 0`), уникальное в пределах списка.
- `title` — строка; после `trim()` длина от 1 до 100; в объект записывается очищенная строка, внутренние пробелы сохраняются.
- `completed` — логическое значение; при создании всегда `false`.
- `priority` — одно из `"low"`, `"medium"`, `"high"`; по умолчанию `"medium"`.

**Файлы:** `src/data.js` — данные (общий набор `demoTasks` и набор варианта); `src/task-service.js` — девять функций логики без вывода и без обращения к глобальным данным; `src/main.js` — демонстрационные сценарии и вывод; `checks.js` — проверки.

**Результаты операций:**

| Функция | При успехе | При ошибке |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект | `undefined`, если задачи нет |
| `getPendingTasks` | новый массив невыполненных задач | — |
| `getTaskTitles` | новый массив названий | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks: новый массив }` | `{ ok: false, error }`, исходные данные не меняются |

**Почему id не равен индексу:** индекс — это текущее место в массиве, он меняется при удалении соседних записей, а `id` идентифицирует запись и остаётся прежним. Поэтому поиск выполняется через `find` по полю `id`, а не через `tasks[id]`.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число можно использовать в дальнейших расчётах и сравнениях. Округление `toFixed(1)` возвращает строку и выполняется только при выводе в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив (через `map`) и новый объект изменяемой задачи (через spread `{ ...task, поле }`). Остальные задачи остаются теми же объектами и не изменяются.

## 5. Общий демонстрационный сценарий

| Этап | Ожидание: всего / выполнено / осталось / прогресс | Фактический результат | Итог |
|---|---|---|---|
| Исходный набор | 4 / 2 / 2 / 50.0% | 4 / 2 / 2 / 50.0% | Совпало |
| Добавление id 20 | 5 / 2 / 3 / 40.0% | 5 / 2 / 3 / 40.0% | Совпало |
| Выполнение id 4 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% | Совпало |
| Переименование id 10 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% | Совпало |
| Удаление id 7 | 4 / 3 / 1 / 75.0% | 4 / 3 / 1 / 75.0% | Совпало |

**Идентификаторы итогового списка:** `[1, 4, 10, 20]`; единственная невыполненная задача имеет `id = 20`.  
**Показанная ошибка и состояние после неё:** попытка добавить задачу с уже существующим `id = 4` вернула `ok: false` с сообщением «Задача с id 4 уже существует». Состояние не изменилось: после отказа сводка осталась 4 / 3 / 1 / 75.0%.  
**Подтверждение неизменности demoTasks:** после всех операций `demoTasks` содержит прежние четыре записи, задача `id = 4` по-прежнему `completed: false`.
