## Что перенесено из ПР2

В работе использованы функции сервиса для создания, поиска, изменения и удаления задач. Логика работы с данными отделена от отображения элементов страницы.

При проверке сервиса протестированы создание задач, проверка идентификаторов, фильтрация, изменение статуса и удаление записей. Также проверено, что операции не изменяют исходные объекты и массивы.

## Эксперименты

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Отсутствующий элемент и коллекция | При поиске отсутствующего элемента будет получено `null`, а пустая коллекция не будет содержать элементов | Результат соответствует ожиданию | `querySelector` возвращает `null`, если элемент не найден |
| 2. dataset и числовой id | Значение из `dataset` будет строкой | Значение получено в виде строки | Атрибуты `data-*` доступны через `dataset`. Для работы с числовым идентификатором требуется преобразование типа |
| 3. Статический NodeList | Ранее полученная коллекция не изменится после добавления нового элемента | Коллекция сохраняет первоначальный состав | `querySelectorAll` возвращает статический `NodeList` |

| 5. Распространение события | Событие от вложенного элемента сможет обрабатываться родительским элементом | Обработчик родительского элемента получает событие | События распространяются по DOM. Для определения нажатого элемента используются `event.target` и `event.currentTarget` |

## Организация кода

- `task-service.js` - содержит логику работы с задачами: создание, поиск, изменение статуса, переименование и удаление.
- `task-selectors.js` - отвечает за выбор задач в соответствии с установленным фильтром.
- `task-view.js` - отвечает за создание карточек задач, отображение списка и обновление сводки.
- `main.js` - связывает обработку событий, работу сервиса и отображение интерфейса.

Полный список задач хранится отдельно от отображаемого списка. Фильтр определяет, какие карточки показывать, но не удаляет скрытые задачи из данных.

События обрабатываются через обработчики приложения. После изменения данных список отрисовывается заново, а сводка обновляется.

## Отладка и клавиатура

Для проверки обработки событий использовалась точка останова в обработчике событий приложения.

- `event.target` - элемент, по которому непосредственно нажали. Это может быть кнопка или вложенный в неё элемент `span`.
- `event.currentTarget` - элемент, на котором установлен обработчик события.
- `dataset.taskId` - идентификатор задачи, полученный из атрибута `data-task-id`. Значение хранится в виде строки.
- `id` - числовой идентификатор задачи, используемый для поиска и изменения данных.
- Действие определяется по кнопке, на которой произошло событие.
- Результат сервиса используется для обновления данных и повторной отрисовки списка.

Проверены переключение статуса задачи, удаление записи и обработка нажатий на вложенные элементы. После повторной отрисовки одно нажатие выполняет только одно действие.

### Проверка клавиатуры

Проверено управление с помощью клавиш Tab, Enter и Space. Фокус можно перемещать между интерактивными элементами, а кнопки доступны для активации с клавиатуры. После изменения статуса и удаления задачи положение фокуса обрабатывается корректно.

Также проверена обработка некорректных идентификаторов. Неизвестный числовой идентификатор `777` не изменяет данные. Строка `4abc` не преобразуется в идентификатор `4`. В обоих случаях некорректное действие отклоняется.
