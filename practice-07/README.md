## Цель и запуск

Цель — перенести модель задач в компонентный интерфейс с локальным состоянием. Из папки `practice-07`: `npm ci`, `npm run dev`. Адрес: `http://127.0.0.1:5173/`. Проверки: `npm test`, `npm run build`, `npm run preview`.

## Реализация

`App` владеет массивом `tasks`, фильтрами, `editingId` и сообщением о результате. `TaskForm` хранит черновик и ошибки полей. В `TaskStats` передаётся статистика всего массива, в `TaskList` — выборка по четырём фильтрам. Дочерние компоненты вызывают переданные обработчики, а `App` обновляет массив через чистые функции `addTask`, `updateTask`, `toggleTask` и `removeTask`. Объекты задач и исходный массив не меняются на месте. Ключ карточки — постоянный `id`; ключ формы меняется при выборе другой записи, поэтому прежний черновик сбрасывается.

Форма проверяет длину названия после `trim`, приоритет и существование категории; строковый `categoryId` переводится в число. Ошибки всех полей показываются возле полей. При ошибке ввода или отказе `onSave` черновик остаётся. Удаление требует подтверждения до обновления состояния. Исходный набор хранится только в памяти страницы: после перезагрузки восстанавливаются 12 задач и начальный фильтр.

## Контрольные вопросы

1. JSX описывает дерево React-элементов, а строка HTML — текст разметки.
2. Props приходят от родителя; состояние принадлежит компоненту и меняется через setter.
3. Обычная переменная при новом рендере создаётся заново и сама не запускает рендер.
4. Функциональное обновление нужно, когда новое значение зависит от предыдущего.
5. Копия массива сохраняет ссылки на объекты; их изменение затронет старые данные.
6. Постоянный `id` сохраняет связь карточки с записью; индекс сдвигается после удаления.
7. Выборка и статистика вычисляются из `tasks` и `filters`, чтобы не синхронизировать копии.
8. Дочерний компонент вызывает переданный ему callback с `id` или значением формы.
9. Управляемое поле получает `value` из state и обновляет его через `onChange`.
10. HTML `select` отдаёт строку; модель задачи требует числовой `categoryId`.
11. Новый `key` размонтирует прежнюю форму и создаёт её с новым черновиком.
12. Подтверждение удаления — побочный эффект; updater состояния должен оставаться чистым.
13. Пустой массив задач и ноль совпадений имеют разную причину; их различают по общей статистике.
14. `npm test` проверяет предметные функции, но не браузерный интерфейс.
15. В ПР8 локальный массив и операции заменяются запросами, добавляются эффект, состояния загрузки и ошибок.
