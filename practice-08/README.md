## Цель и запуск

Цель — подключить React-интерфейс к учебному API. Из папки `practice-08`: `npm ci`; в двух терминалах `npm run api` и `npm run dev`. API: `http://127.0.0.1:5505/api`, интерфейс: `http://127.0.0.1:5173/`. Для проверки: `npm test`, `npm run build`, `npm run preview`.

## Реализация

`App` хранит фильтры, редактируемую запись и уведомление. `useTaskData` владеет последним успешным снимком, состоянием `loading/ready/error`, ошибкой загрузки, ошибкой изменения и флагом `pending`. `task-api` проверяет схему ответов; `api-client` выполняет HTTP-запросы, JSON-разбор, тайм-аут и отмену. В отличие от ПР7, сервер назначает `id`, выполняет фильтрацию и хранит изменения до перезапуска процесса.

Эффект загрузки зависит от `api`, четырёх значений фильтра и счётчика обновлений. Каждый GET имеет свой `AbortController`; cleanup отменяет его и помечает результат устаревшим. Проверка актуальности стоит и после успешного ответа, и после исключения. Мутация блокируется синхронно через `ref`, поэтому два быстрых вызова не отправляют два POST. При размонтировании текущая мутация отменяется. После подтверждённого POST/PATCH/DELETE запускается новый GET с актуальными фильтрами. Ошибка этого GET не превращает уже подтверждённое изменение в ошибку записи. При ошибке записи форма сохраняет черновик.

## Вариант 1

Начальный фильтр — `completed=false`. Сценарий: `PATCH /api/tasks/4` с `{"completed":true}`; затем `GET /api/tasks?completed=false`. После ответа задача 4 больше не входит в выборку. Контракт PATCH и фильтра проверен интеграционным набором; отдельный браузерный прогон варианта не зафиксирован.

## Контрольные вопросы

1. Запрос в теле компонента запускался бы при каждом рендере; эффект связывает его с зависимостями.
2. Cleanup вызывается перед новым эффектом и при размонтировании.
3. `async`-функция возвращает Promise, а эффект должен вернуть функцию cleanup.
4. Нужны `api`, значения фильтров и счётчик обновления; `snapshot` — результат запроса, не его причина.
5. Нестабильный `api` запускал бы лишние загрузки.
6. Подставной или иной API может завершить отменённый запрос; признак актуальности защищает state.
7. Запоздавшая ошибка тоже не должна заменять состояние нового запроса.
8. StrictMode выявляет эффекты без корректной очистки пробного запуска.
9. `pending` обновляется не сразу; `ref` блокирует второй синхронный вызов немедленно.
10. `true` означает подтверждённую запись, даже если последующий GET не удался.
11. После тайм-аута неизвестно, успел ли сервер выполнить POST; повтор может создать дубликат.
12. Смена фильтра касается чтения, а не начатой записи.
13. Отмена ожидания на клиенте не гарантирует отмену операции сервера.
14. `meta.total` считает последнюю отфильтрованную выборку.
15. Браузер нужен для CORS, форм, фокуса, визуального состояния и Network.
