## Цель и запуск

Цель — создать на Express API для чтения задач и категорий. Из папки `practice-09`: `npm ci`, `npm start`. Адрес: `http://127.0.0.1:5505/api`; проверка: `GET /api/health`. Для автоматической проверки: `npm run check:unit`, `npm run check:api`, `npm test`. Другой порт: `npm start -- 5515`.

## Реализация

`validation.js` проверяет и преобразует id и query. `task-service.js` отбирает задачи и ищет запись по id. `store.js` создаёт копии исходных данных для каждого экземпляра приложения. `routes.js` связывает HTTP-маршруты с хранилищем. `app.js` задаёт порядок middleware, CORS, 404 и обработку ошибок; `server.js` открывает порт.

Строка `completed=false` преобразуется явным сравнением, иначе `Boolean('false')` дал бы неверный результат. Все имена query проверяются до преобразования; повторы и неизвестные поля дают `400 INVALID_QUERY`. Для id проверяются вся строка по шаблону и `Number.isSafeInteger`. Маршруты 405 зарегистрированы после GET, поэтому чтение не перехватывается. Ответ OPTIONS формируется раньше маршрутов.

## Контракт и вариант 1

`GET /api/health` возвращает `200` и статус `ok`; `GET /api/categories` — три категории; `GET /api/tasks` — список и `meta.total`; `GET /api/tasks/:id` — одну задачу. HEAD работает для этих путей без тела, OPTIONS возвращает 204. Методы записи на известных путях пока дают `405 METHOD_NOT_ALLOWED` с `Allow: GET, HEAD, OPTIONS`. Отсутствующая задача даёт `404 TASK_NOT_FOUND`, неизвестный путь — `404 ROUTE_NOT_FOUND`.

| Запрос | Проверенный результат |
|---|---|
| `GET /api/tasks?completed=false` | 200, id 4, 7, 13, 19, 22, 28, 34; `meta.total: 7`. |
| `GET /api/tasks?completed=0` | 400 `INVALID_QUERY`. |
| `GET /api/tasks/4` | 200, задача с id 4. |
| `GET /api/tasks/2` | 404 `TASK_NOT_FOUND`, `details.id: 2`. |

`meta.total` — число записей после фильтрации. Пустая выборка возвращается как `200` и `data: []`. Результаты таблицы подтверждены HTTP-тестами; отдельные команды `curl` не выполнялись.

## Контрольные вопросы

1. В Node.js JavaScript работает без браузерного DOM; доступны серверные API.
2. Маршрут выбирается по HTTP-методу и пути; query обрабатывается внутри маршрута.
3. `req.params` содержит части пути, query — параметры после `?`.
4. Строка `'false'` непустая; её нужно сравнить с допустимым значением.
5. Частичный `parseInt` принял бы `4abc`; безопасное целое исключает неточные id.
6. Пустой список — успешный результат поиска; отсутствующий ресурс — 404.
7. `TASK_NOT_FOUND` относится к задаче, `ROUTE_NOT_FOUND` — к пути.
8. 405 означает известный путь с запрещённым методом; `Allow` перечисляет допустимые.
9. `meta.total` — размер возвращённого списка с учётом фильтров.
10. Ранний обработчик может перехватить запрос до нужного маршрута.
11. Четыре параметра отличают Express-обработчик ошибок от обычного middleware.
12. `createApp()` позволяет тестировать сервер на свободном порту без запуска при импорте.
13. При 500 клиент получает общий код и сообщение без стека и внутренних данных.
14. CORS разрешает чтение из браузера, но не проверяет личность клиента.
15. В ПР10 нужны POST/PATCH/DELETE, серверная валидация записи и расширение Allow.
